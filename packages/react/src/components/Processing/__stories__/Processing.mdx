## Overview

Processing indicates that data is being loaded or an action is in progress. It
is used in chat interfaces, async operations, and anywhere the user should wait
for a response. Inspired by the Carbon Design System loading pattern, this
component extends it with shape formation transforms and an imperative animation
API.

`mode` sets the sequence that runs on mount. `square` and `wiggle` load in

## Accessibility

- The root element is `role="status"` with an `aria-label` taken from `label`
  (default `'Processing'`). Keep it aligned with the user-facing status message.
- **Reduced motion is handled in JavaScript.** The dots are animated with the
  Web Animations API, which a CSS `prefers-reduced-motion` rule cannot stop, so
  the component reads the preference itself and paints a static end state
  instead: `loading` and `wiggle` show three resting dots, `triangle` and
  `square` show the formed shape, and `out` hides the dots. The imperative
  handle snaps to the same end states, and `triggerWiggle()` does nothing. The
  same static state is used where the Web Animations API is unavailable.

## Proposed v2.0 update

Processing v2.0 moves the animation from CSS keyframes to the Web Animations API
and adds shape formations, an imperative handle, and an accessible status
region. The default `loading` experience now remains active until a new mode is
triggered.

### Intended use cases

- Keep `loading` as the default state for waiting, thinking, or background work
  in progress.
- Trigger `triangle` or `square` when the system needs to communicate a more
  expressive state change after loading completes.
- Use `wiggle` as lightweight feedback when work is still active but you want a
  brief accent rather than a persistent new formation.
- Use `out` to intentionally dismiss the indicator when work is complete or
  cancelled.

### Interaction guidance

- Start in the default loading state, then trigger a new mode only when the
  product has a meaningful state transition to communicate.
- Prefer imperative handle methods for transitions so the element can respond to
  async milestones without remounting the surrounding UI.
- Treat the new modes as optional enhancements, not replacements for the base
  indicator.
- Keep the accessible label aligned with the user-facing status message when
  embedding Processing in larger workflows.

### Proposed behavior and usage model

v2.0 adds an imperative handle (via `ref`) for moving between states without
remounting:

- `triggerTriangle()` highlights a completed or elevated in-progress state.
- `triggerSquare()` introduces a four-dot formation for an alternate expressive
  state.
- `triggerWiggle()` provides transient motion feedback without leaving the
  loading layout.
- `triggerOut()` cleanly dismisses the current indicator from any visible state.

### Migration guidance

**Unchanged:** the package name, the `Processing` import, the SCSS import, and
the `loop` prop. `<Processing />` and `<Processing loop />` keep working without
code changes.

**New:** the `mode`, `label`, `ai` and `className` props, the imperative handle,
the `role="status"` region, and reduced-motion support.

**Breaking changes to review before upgrading:**

- **Loop length.** In v1, `loop` ran five cycles and then unloaded. In v2 the
  loading loop repeats until the mode changes or `triggerOut()` is called.
  `loop={false}` still runs one cycle and then unloads.
- **CSS classes.** The `__linear` and `__linear--no-loop` modifier classes and
  their keyframes are removed. Overrides that targeted them no longer apply.
- **Rendering needs JavaScript.** The dots are drawn and animated from
  JavaScript, so nothing is visible before hydration, whereas the v1 CSS
  animation ran without it.
- **Right-to-left.** v1 mirrored the load stagger under `[dir='rtl']`; v2 always
  staggers left to right.
- **Stories.** The `LinearLoop` and `LinearNoLoop` stories are replaced by
  `Loading`, `Triangle`, `Square`, `Wiggle` and `Interactive`, so links to the
  old story IDs will break.

## Example usages

#### Default loading behavior

Starts in the loading state and remains there until your product triggers a new
mode.

```jsx
<Processing />
```

#### Transition to triangle

Start in the default loading state, then trigger the triangle mode when a
product milestone completes.

```jsx
import { useRef } from 'react';
import { Processing } from '@carbon-labs/react-processing/es/index';
import type { ProcessingHandle } from '@carbon-labs/react-processing/es/index';

function App() {
  const ref = useRef<ProcessingHandle>(null);

  // Call when the product milestone completes.
  const handleComplete = () => {
    ref.current?.triggerTriangle();
  };

  return (
    <>
      <Processing ref={ref} label="Processing" />
      <button onClick={handleComplete}>Complete</button>
    </>
  );
}
```

#### Transition to square

Use the imperative handle when the workflow needs a four-dot formation to
communicate a distinct state.

```jsx
import { useRef } from 'react';
import { Processing } from '@carbon-labs/react-processing/es/index';
import type { ProcessingHandle } from '@carbon-labs/react-processing/es/index';

function App() {
  const ref = useRef<ProcessingHandle>(null);

  const handleStateChange = () => {
    ref.current?.triggerSquare();
  };

  return (
    <>
      <Processing ref={ref} label="Processing" />
      <button onClick={handleStateChange}>Change state</button>
    </>
  );
}
```

#### Wiggle

Trigger a left-to-right bob animation on the three loading dots via the
imperative handle.

```jsx
import { useRef } from 'react';
import { Processing } from '@carbon-labs/react-processing/es/index';
import type { ProcessingHandle } from '@carbon-labs/react-processing/es/index';

function App() {
  const ref = useRef<ProcessingHandle>(null);

  return (
    <>
      <Processing ref={ref} />
      <button onClick={() => ref.current?.triggerWiggle()}>Wiggle</button>
    </>
  );
}
```
