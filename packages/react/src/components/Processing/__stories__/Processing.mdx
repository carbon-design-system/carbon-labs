## Overview

Processing indicates that data is being loaded or an action is in progress. It is used in chat interfaces, async operations, and anywhere the user should wait for a response. Inspired by the Carbon Design System loading pattern, this component extends it with shape formation transforms and an imperative animation API.

A Figma component kit for Processing is currently in development. When available, it will include all four modes and both light and dark theme variants matching the Carbon dot colour tokens.

## Proposed v2.0 update

Processing v2.0 extends the current element with reviewer-friendly interactive modes while preserving the existing base loading behavior. The default `loading` experience now remains active until a new mode is triggered, removing the need to differentiate between separate loop and no-loop Labs stories.

### Intended use cases

- Keep `loading` as the default state for waiting, thinking, or background work in progress.
- Trigger `triangle` or `square` when the system needs to communicate a more expressive state change after loading completes.
- Use `wiggle` as lightweight feedback when work is still active but you want a brief accent rather than a persistent new formation.
- Use `out` to intentionally dismiss the indicator when work is complete or cancelled.

### Interaction guidance

- Start in the default loading state, then trigger a new mode only when the product has a meaningful state transition to communicate.
- Prefer imperative handle methods for transitions so the element can respond to async milestones without remounting the surrounding UI.
- Treat the new modes as optional enhancements, not replacements for the base indicator.
- Keep the accessible label aligned with the user-facing status message when embedding Processing in larger workflows.

### Proposed behavior and usage model

The proposed v2.0 surface keeps the current base props and imperative handle intact while clarifying the recommended usage model for these transitions:

- `triggerTriangle()` highlights a completed or elevated in-progress state.
- `triggerSquare()` introduces a four-dot formation for an alternate expressive state.
- `triggerWiggle()` provides transient motion feedback without leaving the loading layout.
- `triggerOut()` cleanly dismisses the current indicator from any visible state.

### Migration guidance

Migration from the current Processing element is additive:

- Existing implementations that use the default loading behavior do not need to change.
- The v2.0 proposal removes the need for separate loop and no-loop story variants in Labs because Processing now remains in the loading state until another mode is triggered.
- Existing `label` and `ai` usage stays valid.
- Teams only need migration work when they want to opt into the new interaction modes by using the imperative handle in response to product events.
- Adoption can happen incrementally, one mode at a time, without altering the base loading behavior.

## Example usages

#### Default loading behavior

Starts in the loading state and remains there until your product triggers a new mode.

```jsx
<Processing />
```

#### Transition to triangle

Start in the default loading state, then trigger the triangle mode when a product milestone completes.

```jsx
import { useRef } from 'react';
import { Processing } from '@carbon-labs/react-processing';
import type { ProcessingHandle } from '@carbon-labs/react-processing';

function App() {
  const ref = useRef<ProcessingHandle>(null);

  const handleComplete = () => {
    ref.current?.triggerTriangle();
  };

  return <Processing ref={ref} label="Processing" />;
}
```

#### Transition to square

Use the imperative handle when the workflow needs a four-dot formation to communicate a distinct state.

```jsx
import { useRef } from 'react';
import { Processing } from '@carbon-labs/react-processing';
import type { ProcessingHandle } from '@carbon-labs/react-processing';

function App() {
  const ref = useRef<ProcessingHandle>(null);

  const handleStateChange = () => {
    ref.current?.triggerSquare();
  };

  return <Processing ref={ref} label="Processing" />;
}
```

#### Wiggle

Trigger a left-to-right bob animation on the three loading dots via the imperative handle.

```jsx
import { useRef } from 'react';
import { Processing } from '@carbon-labs/react-processing';
import type { ProcessingHandle } from '@carbon-labs/react-processing';

function App() {
  const ref = useRef<ProcessingHandle>(null);

  return (
    <>
      <Processing ref={ref} />
      <button onClick={() => ref.current?.triggerWiggle()}>Wiggle</button>
    </>
  );
}
```

#### Imperative handle

Use a ref to trigger animations programmatically — for example, forming a triangle when an async operation completes.

```jsx
import { useRef } from 'react';
import { Processing } from '@carbon-labs/react-processing';
import type { ProcessingHandle } from '@carbon-labs/react-processing';

function App() {
  const ref = useRef<ProcessingHandle>(null);

  // When your async work finishes, call triggerTriangle() on the ref:
  return <Processing ref={ref} />;
}
```
